# Короткая шпаргалка к защите ЛР4

**Аутентификация** — проверка, кто пользователь. В проекте email/password проверяются в PostgreSQL, после чего выдаётся JWT.

**Авторизация** — проверка, что пользователь имеет право выполнить действие. Middleware запрещает методы создателя без корректного Bearer JWT.

**JWT** — подписанный токен из header, payload и signature. В payload хранится `user_id`, стандартные `iat`, `exp`, `jti`. Сервер проверяет подпись и срок действия.

**Authorization header** — `Authorization: Bearer <jwt>`.

**Redis blacklist** — logout не может физически «удалить» уже выданный JWT, поэтому его `jti` помещается в Redis до `exp`. Middleware проверяет blacklist при каждом защищённом запросе.

**Почему TTL** — после истечения JWT запись blacklist больше не нужна и Redis удаляет её автоматически.

**Swagger/OpenAPI** — машиночитаемое описание контрактов HTTP API и UI для выполнения запросов.

**Cookie** — небольшие данные браузера, автоматически отправляемые серверу для подходящего домена/path. В Go-варианте этой ЛР основная авторизация сделана через JWT, а не cookie-session.

**Сессия** — серверное состояние пользователя, обычно идентификатор сессии хранится в cookie, а данные сессии — на сервере/Redis. В нашем Go-варианте вместо серверной сессии используется JWT и Redis blacklist.

**SSO** — единая аутентификация, при которой один вход даёт доступ к нескольким связанным системам.

**2FA** — второй фактор помимо пароля, например одноразовый код или аппаратный ключ.

**RSA** — асимметричный алгоритм с открытым и закрытым ключами. JWT может подписываться RSA, но в учебном проекте используется HS256 с общим секретом.
