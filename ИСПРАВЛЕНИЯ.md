# Пояснения по исправлениям ЛР-3

## 1. В API оставлено ровно 10 бизнес-методов

Из регистрации маршрутов удалены лишние совместимые алиасы:

- `POST /api/users/register`;
- `POST /api/auth/login`;
- `POST /api/auth/logout`.

После исправления в приложении зарегистрированы ровно 10 бизнес-методов:

1. `GET /api/launch-vehicles` — получение списка опубликованных услуг.
2. `GET /api/feed` — получение элемента ленты.
3. `GET /api/launch-vehicles/draft` — получение черновика текущего пользователя.
4. `POST /api/launch-vehicles` — создание черновика услуги.
5. `PUT /api/launch-vehicles/draft` — публикация черновика.
6. `DELETE /api/launch-vehicles/:id` — мягкое удаление своей услуги.
7. `POST /api/launch-vehicles/:id/like` — установка или снятие лайка.
8. `POST /api/users` — регистрация пользователя.
9. `POST /api/users/login` — вход пользователя.
10. `POST /api/users/logout` — выход пользователя.

Изменённый файл: `internal/api/server.go`.

## 2. В ответ ленты добавлен второй признак 0/1

В структуру `LaunchVehicleFeedItem` добавлено поле:

```json
"is_creator": 1
```

Теперь ответ `GET /api/feed` содержит два разных признака:

- `liked` равен `1`, если текущий пользователь поставил услуге лайк, иначе `0`;
- `is_creator` равен `1`, если `creator_id` услуги совпадает с `model.CurrentCreatorID()`, иначе `0`.

Существующие поля JSON и логика поля `liked` не изменены.

Пример части ответа ленты:

```json
{
  "id": 1,
  "creator_id": 1,
  "liked": 0,
  "is_creator": 1
}
```

Изменённый файл: `internal/app/serializer/serializer.go`.

## 3. Уточнено описание API в README

В разделе REST API:

- явно указано, что в приложении ровно 10 бизнес-методов;
- все методы пронумерованы от 1 до 10;
- удалены упоминания лишних алиасов;
- добавлены примеры URL с идентификатором услуги;
- объяснена работа ленты без параметров и с параметрами;
- отдельно описано назначение полей `liked` и `is_creator`.

Логика ленты описана следующим образом:

- `GET /api/feed` без `id` возвращает первый элемент со статусом `published`;
- `GET /api/feed?id=<id>&next=true` возвращает следующий опубликованный элемент после указанного `id`;
- это два варианта вызова одного метода `GET /api/feed`, а не два разных бизнес-метода.

В Postman два варианта объединены в один запрос с необязательными параметрами `id` и `next`. Параметры можно включать и выключать, поэтому коллекция теперь содержит ровно 10 элементов.

Изменённый файл: `README.md`.
